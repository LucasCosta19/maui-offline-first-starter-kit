Support center

Start with reproducible diagnostics.

The product is designed for developers. The fastest support path is self-service documentation first, followed by a structured issue report when something remains unresolved.

1. Start with the included docs

Inside the source package, begin with:

  • README.md
  • docs/GETTING_STARTED.md
  • docs/ARCHITECTURE.md
  • docs/OFFLINE_FIRST_AND_SYNC.md
  • docs/TROUBLESHOOTING.md
  • docs/ADDING_A_SYNCED_ENTITY.md

2. Verify the environment

Before reporting a build/runtime problem, record:

  • Operating system
  • dotnet --info
  • dotnet workload list
  • Target platform
  • Exact command used
  • Complete error text

Do not send secrets

Never include:

  • passwords
  • JWT access/refresh tokens
  • production signing keys
  • private certificates
  • API secrets
  • customer production databases

Support scope

Reasonable technical assistance during the Technical Validity Period relates to the documented functioning of the purchased version.

It does not include custom application development, implementing the buyer's domain, infrastructure administration, migration of a buyer-specific system, 24/7 support or an SLA unless separately agreed.

Good support requests

Reproducible Exact error Environment included No secrets

A small, reproducible report is usually much faster to diagnose than screenshots without context.

Before requesting feature work

Please distinguish a product defect from custom implementation. Requests such as adding a buyer-specific entity, changing the buyer's deployment architecture or integrating a third-party business system are custom development rather than product support.
